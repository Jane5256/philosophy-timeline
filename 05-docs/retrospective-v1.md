## 一句话总览

一个**没有代码基础的交互设计师** + 工程助手（Claude），把一张静态信息图，做成了一个**有独特视角（东西方思想同期对照）、数据驱动、可缩放、已上线可分享**的中文交互网站。核心方法：**设计师定方向、数据打地基、工程做实现并每步可见地验证。**

## 经验教训（可复用）

1. **先盘真相，再做规划。** 文档会过时，代码和数据不会撒谎。
2. **给非技术伙伴"拍板"，而不是"选择题"。** 把技术当画笔。
3. **数据驱动是最大的省力杠杆。** 内容结构化后 UI 自动生成、扩展只改数据。
4. **最该早做的是"诚实的价值批判"。** 动手前一句"护城河浅"比做完重来值钱。
5. **先验证、再投入。** 用真实数据先跑一遍，编码前就暴露缺口与可行性。
6. **每一步都要"看得见"。** 截图即时自检，把"我以为对了"变成"我确认对了"。
7. **小步快跑、频繁上线。** 早拿可分享链接、每次验证部署，问题暴露在小处。
8. **卡住先诊断根因，别瞎试。** "构建失败"实为"额度用尽"；干净重建排除代码因素。
9. **遇阻找务实绕行路。** 目标是"上线"，不是"用某种方式上线"。
10. **为真实受众想最后一公里。** 想清楚受众在哪、网络环境如何（被墙资源）。
11. **模型的记忆不在脑子里，在文件里。** 不写进 `memory/` 与 TODO，下次会话就等于没发生——本项目早期几次会话没存记忆，连续性就断了。

## 工时（净产出口径）

> 仅计 Claude 实际"动手产出"的时间：已剔除①用户审阅/决策时间（由用户自行估算）、②Netlify 额度用尽那场一次性波折（约 1–2h 轮询/排查/迁移，2.0 不会再遇到）。基于工作量估算，非秒表读数。

**1.0 净产出 ≈ 6–8 小时**

| 模块 | 净产出 | 说明 |
|---|---|---|
| 数据层（东方 37 人 + 流派 + 朝代 + 西方补缺 + convert）| ~2–3h | 主要是内容考据撰写 |
| 前端骨架 + 十几轮打磨 | ~3–4h | 每轮 = 改码 + 构建 + 截图自检 |
| 头像 + 本地化 | ~1h | 下载后台跑，不占 |
| 部署配置（不含 Netlify 波折）| ~0.5h | 纯配置动作很快 |

- 折算传统人力等效：约 3–5 周 / 120–180 人时（1 设计师 + 1 前端）。
- **2.0 换算尺（净产出）**：单功能多在 0.5–2h——移动端 ~1–1.5h｜母题追踪 ~2h（含打标签）｜邹衍补图 ~0.3h｜AI 思想对话 ~3–4h（含接 API）。
- 注：用户侧投入（审阅 + 拍板，每轮几分钟到十几分钟，越主观的视觉/交互看得越多）不计入此口径，由用户自行估算——这部分是项目质量的来源，非浪费。
